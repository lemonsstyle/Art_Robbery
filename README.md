# 神偷大盗 · Art Robbery Online

Reiner Knizia《神偷大盗 / Art Robbery》的在线朋友局实现。服务端权威判规则，浏览器端只发操作意图；支持 2–5 人房间、断线重连、掉线托管和再来一局。

所有牌面、圆片、图标都由代码生成，没有位图素材：卡牌用 CSS + SVG 排版，圆片用 CSS 圆形与几何图标组合；动作音效由 Web Audio 实时合成，快捷语语音是离线 TTS 文件。

## 技术与结构

- `client` — React 19 + Vite 7：界面、牌桌、动效与 WebSocket 客户端。
- `server` — Node.js + `ws`：房间、座位、重连、服务端权威状态机和静态资源托管。
- `shared` — 纯 TypeScript：规则引擎、牌库/圆片数据、事件文案、前后端共享类型。
- `神偷大盗-规则整理.md` — 原始规则整理与待核实清单。
- `apple-design.md` — 界面与交互的判断标准。

## 一局游戏怎么流转

1. 浏览器只发“意图”（`play`、`chooseTile`、`chooseSteal` 等）。`server/src/index.ts` 校验会话后调用 `Game` 的对应方法。
2. `shared/src/engine.ts` 是唯一规则来源：修改状态、写入 `events`，再由 `buildView` 生成每个玩家各自的视图（自己的手牌在 `you.hand`，其他玩家只有 `handCount`）。
3. 客户端不自己判规则，只渲染 `view`；`view.seq` 变化时，用本批 `events` 触发飞牌、圆片移动、小狗和音效。
4. 阶段：`LOBBY` → `PLAYING` →（中央圆片拿完）`RAID_END` → 下一轮 `PLAYING` → … → `GAME_END`。
5. 一个回合：出牌 → 必要时进入 `pending`（选圆片 / 选抢谁 / 贪心贼 / 看门狗）→ 结算并补牌 → 下一位。中央 9 枚圆片拿完即结束本轮。
6. 轮末：检查老板是否保住 → 本轮圆片标记 `secured` → 手牌保留、牌堆不洗；持狗者下一轮先手。

### WebSocket 协议

- 客户端 → 服务端：`create`、`join`、`rejoin`、`start`、`play`、`chooseTile`、`chooseSteal`、`chooseGreedy`、`dogResponse`、`quickChat`、`rematch`、`leave`、`ping`。
- 服务端 → 客户端：`session`（房间码、玩家 ID、重连令牌）、`state`（完整 `GameView`）、`error`、`left`、`superseded`、`pong`。
- 任何合法操作都会广播新的 `state`；客户端不要本地推进回合，也不要自己计算得分。

## 复制邀请链接 / 房间码

- HTTPS 或 localhost 下优先使用 Clipboard API。
- 通过局域网 HTTP 访问时，Clipboard API 不可用，会自动降级到隐藏 textarea + `execCommand("copy")`。
- 如果浏览器仍拦截复制，页面不会再弹出阻塞式 prompt，而是显示一个自动选中的只读输入框，让玩家手动复制链接或房间码。
- “复制邀请链接”和“只复制房间码”各自有独立的成功/失败反馈。

## 已实现规则

- 2–5 人，固定 4 轮（素描 / 雕塑 / 古董 / 画作），每轮 9 枚圆片。
- 55 张牌：数字 0–5 各 6 张、老板 6 张、看门狗 6 张、贪心贼 7 张。
- 回合三步：出 1 张牌 → 拿 1 枚圆片 → 补 1 张牌；手牌始终 5 张。
- 数字牌：中央同值圆片任选一枚；如果这些圆片的数值和白点完全相同，则自动拿取，不再询问；中央没有则从其他玩家手里抢；没有目标就无事发生。
- 老板牌：拿老板圆片（可从中央或别人手里拿）；轮末没有同轮 4/5 则回盒。
- 看门狗：拿走狗；被抢时可选择交狗保圆片，或交圆片留狗。
- 贪心贼：从中央任取一枚，包括老板圆片，但不能抢人；如果中央剩下的圆片在种类、数值和白点上完全一样，则自动拿第一枚。
- 轮末：老板检查、圆片扣放、手牌保留、牌堆不洗、持狗者下一轮先手。
- 终局：3–5 人白点最少者出局（并列一起出局）；2 人局改为扣 10 分；再比战利品总分，平分比白点。

### 实现中的判断

规则书没有写死的地方，按以下默认实现，并在代码里集中成可改的数据/逻辑：

- 每轮圆片构成为 `0,1,2,3,3,3,4,5 + 老板`；官方规则书图示只明确了第 1 轮，后三轮按同构实现。
- 白点分布：第 1 轮 `0=2`；第 2–4 轮 `0=2, 1=1`。这是根据官方图示和中文讲解视频推断的，集中在 `shared/src/data.ts` 的 `ALIBI_DOTS`，拿到实物后可直接改表。
- 数字牌不能拿老板圆片；老板牌可以抢别人手里的老板圆片。
- 2 人局罚分按“扣 10 分，但不超过战利品总分”实现。
- 2 人局白点并列最少时，双方都扣分（规则书未规定）。
- 对手的圆片在数字版中公开显示；实体版是扣放，但获取过程本来就是公开信息。
- 第 1 轮没人拿狗时，下一轮由上一轮先手继续先手，狗留在中央。
- 掉线：普通出牌者掉线 12 秒后自动出牌；待决策者掉线 6 秒后自动选第一项；看门狗待决策 20 秒后默认交出圆片；大厅掉线座位保留 90 秒。

## 设计说明

### 视觉：编辑现代主义

参照 Pentagram / COLLINS 一类顶级平面设计公司的编辑设计语言，而不是“桌游皮肤”：

- 瑞士网格、严格对齐、超大字号、极少装饰。
- 黑 / 米白 / 品牌红三色骨架，四轮用金、钴蓝、赭红、森林绿区分。
- 卡牌是排版作品：居中大数字、细边框；特殊牌用几何 SVG 图标和大号中文名，不显示角标和英文标签。
- 圆片是圆形信息件：大数值、轮次色外环、白点直接画在底部。
- 所有牌面由 React 组件按数据渲染，改数值/白点不需要重新出图。

### 动作可读性

- 电脑端与手机一致：顶部对手得分圆片、中间中央牌桌、底部自己的手牌与赃物。桌面尺寸更大、信息更宽松；对手的手牌数量不在玩家界面显示。
- 手机端为单屏上下布局：顶栏、对手条、牌桌和底部手牌都压在 `100dvh` 内，页面不滚动；短屏会自动缩小圆片和手牌。
- 出牌时卡牌从手牌/对手席位先抬升、再飞向牌桌中央；拿片时圆片从固定槽位先单独抬起、短暂停顿，再飞向拿片者的得分区，目标圆片等飞行到位后才出现。
- 中央圆片固定为从 0 到 5、老板在最后的 3×3 九宫格；被拿走的槽位留空，位置不重排，方便按大小寻找和点击。
- 不再用动作弹窗打断对局；中央牌桌**底部**居中保留最近一句动作（对手显示为“对方”，自己显示为“你”）。右侧不再有动作记录按钮，记录只从顶栏的“最近动作”图标打开，按时间倒序回看 30 条。
- 被抢时受害者席位会震动，圆片/看门狗/老板用红、蓝、金色拖影飞行，并在原位先出现拾取光环；新持有者会有对应颜色的脉冲高亮。
- 看门狗移动时不是普通圆片：一只四条腿会跑、尾巴会摇的小狗会沿弹跳路径跑过去，带“汪!”气泡和一路爪印。
- 每轮清算时，老板圆片没有同轮 4/5 的玩家会在轮末过场里看到“老板失效 · 玩家名”的提示和印章动画；第四轮则在终局弹窗提示。
- 已结束轮次的圆片不再逐个显示数值，而是在各自席位/底部控制台变成**筹码堆**（显示枚数和轮次名，不显示分值）。
- 自己的手牌、当前轮赃物和已封存筹码在底部控制台，始终可见；对手当前轮圆片放大到 52px（手机 44px）并居中。
- 中央牌桌不再显示牌堆、弃牌和老板/看门狗的位置文字，圆片固定九宫格。老板在桌上时牌桌整块偏金色，看门狗在桌上时整块偏钴蓝；被玩家拿走时，该玩家的席位和底部手牌面板整块变成对应颜色，并保留“持有老板 / 持有看门狗”徽章。
- 老板圆片用**内描边**金环，不再向外加投影，视觉尺寸和数字圆片一致。
- 每位玩家当前轮的得分牌按数值从小到大排列，老板圆片排在数字牌之后。数字牌只显示居中数值，没有角标和小黑点。
- 看门狗二选一使用两张大型选项卡：交出看门狗/保住圆片、交出圆片/保住看门狗；不再使用长段说明。
- 轮到谁出牌用多层提示：牌桌顶栏的大号回合条、当前席位的红色脉冲环和“出牌中”标签、自己底部面板的红边和“轮到你出牌”徽章；非当前回合的手牌会降亮度。
- 底部自己的区域是同一行：左侧当前轮得分牌与已封存筹码，中间手牌；手牌上的英文标签、英文牌名和 B/D/G 字母都移除了。
- 打出数字牌时，如果中央同值圆片的数值和白点完全一样，会自动拿一枚，不再让玩家做无意义的选择。
- 终局计分在总分下为每位玩家列出素描/雕塑/古董/画作四段赃物得分。
- 全部动作都有 Web Audio 合成音效：出牌、拿片、抢牌、看门狗、老板、轮次、提示、胜负；顶栏可一键静音。

### 交互与动效：按 `apple-design.md`

- **清晰**：任何时刻都能看到轮到谁、自己该做什么、上一动作发生了什么；待决策的圆片会脉冲高亮，只有合法目标可点。
- **谦让**：界面用米白和细线退到背景；红/黑只留给当前回合和关键动作。
- **纵深**：弹层、回合过场、发牌和圆片入场用同一套缓动；动效只解释“什么从哪来、到哪去”。
- **直接操作与反馈**：点牌选中、再点打出，双击直接打出；Enter 确认、Esc 取消；出牌、拿片、轮末、终局都有即时状态变化和事件文案。
- **一致**：按钮、输入、卡牌、圆片、弹层共用一套尺寸、圆角、字重和间距 token。
- **无障碍**：语义化按钮、`:focus-visible`、`aria-live` 状态、键盘操作、足够大的触控面积，以及 `prefers-reduced-motion` 下关闭动效。
- **移动端**：整局固定在一屏内，页面不滚动；短屏自动缩小圆片和手牌。

## 快捷语与语音

- 底部玩家面板有一个深色“快捷语”气泡按钮，手机上同样显示文字，不是只有小图标。
- 点开后是 6 条固定短语，点击会同时发送文字气泡和对应语音；发送者和房间内其他在线玩家都会看到气泡。
- 语音文件在 `client/public/audio/chat-1.mp3` 到 `chat-6.mp3`，是用在线 TTS 按原文逐条生成的，没有直接搬运有版权的网络音频。
- 语音播放遵循顶栏的静音开关；浏览器未授权自动播放时会静默失败，但文字气泡仍然显示。
- 服务端只接受白名单里的快捷语 ID，并做了 800ms 发送间隔限制。

## 终局结算

- 每位玩家一张排名卡：名次/出局、总分、四轮分段赃物、白点、罚分和计算式。
- 2 人局会明确显示 `赃物 54 − 罚分 10 = 44`。
- 被逮捕的玩家显示“赃物总额”和“白点最少，不计名次”，不会混入正常排名。
- 胜者使用金色卡片、皇冠和赢家标签；并列胜者会同时标记。

## 已知限制

- 房间和对局保存在内存里，服务重启会清空。
- 对连接中的玩家没有强制出牌超时；只对掉线玩家做自动出牌、待决策自动选择和看门狗超时。挂机玩家可能让房间一直等待。
- 没有观战、自由文本聊天、持久化存档和请求限流（快捷语白名单除外）；这是面向朋友的私有桌，不是公开大厅。
- 代码已纳入本地 Git；首次推送前需要配置远程仓库（`git remote add origin <仓库地址>`）和凭据。

## 运维

- 健康检查：`GET /health` 返回房间数、在线玩家数、uptime。
- 静态资源：`/assets/*` 长缓存，`index.html` no-cache。
- 安全响应头：CSP、`X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`。
- 房间清理：无人在线超过 2 小时的房间会被回收；大厅掉线座位 90 秒后移除。
- 服务日志：`journalctl -u art-robbery -f`；重启后房间清空是预期行为。
